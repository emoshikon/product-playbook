# API initiative reference

Use only when an initiative exposes an API or interface contract.

Consider: endpoint purpose; consumer and workflow; request/response field semantics, requiredness and types; error behavior; pagination and idempotency if relevant; authentication and authorization; compatibility and versioning; latency and reliability promises; representative success, no-result, invalid-input and ambiguous cases.

Link schemas and API examples from the relevant capability, explaining what each defines and whether it is agreed, proposed, or illustrative. Fine details can live in these artifacts without duplication in requirements prose. Use an inline specification or example when it helps understanding. Agreed API examples can define expected behavior and later inform tests. Resolve conflicts between prose, schemas, and examples rather than assuming one automatically overrides the others.
