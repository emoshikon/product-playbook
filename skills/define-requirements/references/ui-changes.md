# UI initiative reference

Use only when an initiative changes a user-facing interface.

Consider: target users and jobs, primary flow, entry and exit points, empty/loading/error states, permissions, accessibility, responsive behavior, copy and terminology, instrumentation, edge cases, and compatibility with existing journeys.

Link designs, mockups, or prototypes from relevant features, identifying what they define and whether they are agreed, proposed, or illustrative. Agreed mockups can define interaction and visual details without repeating all of them in prose. Resolve conflicts between the linked designs and written behavior. Acceptance criteria should describe observable user behavior, not dictate frontend component architecture.
